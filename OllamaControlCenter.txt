## Platform and technical requirements

| ID | Requirement |
|---|---|
| T1 | Written in **Go**, using only the standard library (no C compiler needed). |
| T2 | Runs on Windows 11, macOS, Linux and the DGX Spark (ARM64), as one executable per OS and CPU. |
| T3 | Nothing to install on the machine that runs it. |
| T4 | The interface is a built-in web page opened in a browser tab, not a native window. |
| T5 | The page works in light and dark mode. Information is never shown by colour alone: symbols and text are used too. |
| T6 | Can monitor a remote Ollama, for example your Windows laptop pointing at the Spark. |
| T7 | Every line of source code has a comment. |

## Security requirements

| ID | Requirement |
|---|---|
| S1 | The web page listens on the local machine only by default (`127.0.0.1:8765`). Letting other machines in must be a setting you choose. |
| S2 | Only the monitor's own page can use the Stop and Unload buttons. Other websites can't trigger them. |
| S3 | The program only unloads a model that is currently loaded and idle. |
| S4 | No prompt or response text is stored anywhere. |

## Functional requirements

| ID | Requirement |
|---|---|
| F1 | Detect whether Ollama is reachable and show **online/offline**. |
| F2 | Show each loaded model in a table with these columns: model, **purpose**, size, memory, context length, time until unload. |
| F3 | The Purpose column describes what each model is for. Where it comes from (detected by Ollama, your own label, or both) is still to be confirmed. |
| F4 | An **Unload** button on each model row that is only enabled when that model is idle (not serving a request). It asks for confirmation first. |
| F5 | An API health panel: reachable, response time, Ollama version, failed checks in a row and in total, and the last successful check. |
| F6 | Start on demand with one command and stop with a **Stop button** or Ctrl+C. Nothing keeps running afterwards. |
| F7 | A terminal mode (a single check, or continuous watching) as a fallback. |
| F8 | Graphics: a state timeline, an API response-time line chart, memory per loaded model, an unload countdown, and an uptime/failure summary. |
| F9 | An event log of changes, for example "12:03 model loaded". |
| F10 | An adjustable **settings panel**: Ollama address, poll interval, request timeout, chart history length (default 30 minutes), theme (light, dark or follow the system), whether other machines can open the page, and optional saving of history to a file. |
| F11 | Manual pause and resume of monitoring, and a manual refresh. |
